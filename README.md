# Mai Persona

为 MaiBot 角色维护**内在状态**的第三方插件：情绪与心境、个人日程、事件线、对用户的关系与好感、待办和日记。它让长期互动更连贯，但**不接管人格、不设置回复风格、不写入长期记忆**。

当前版本 `0.1.9`，面向 MaiBot `1.3.x` / `maibot-plugin-sdk` `2.20.x`，MIT 许可，作者 [Orxil.V](https://github.com/hedgehogovo)。

**人格边界：MaiBot 自有人格设置是角色身份、总体行为准则和回复风格的唯一来源。** Mai Persona 只补充内在状态与个人生活模拟，不覆盖 MaiBot 的人格，也不改变本轮用户任务的优先级。发生冲突时，以 MaiBot 原生配置和本轮任务为准。

---

## 和同类插件有什么不同

MaiBot 插件中心里与"拟人"相关的插件，大多各解决**一个表现**：主动发话、日程生成、好感数值、人格演化、记忆存储、打字速度……Mai Persona 的定位是这些表现背后的**状态层**：先有可解释、可回溯的情绪/生活/关系状态，再由 MaiBot 自己的 Planner 和 Replyer 决定怎么说话。

| 方向 | 常见做法 | Mai Persona 的做法 |
| --- | --- | --- |
| 主动消息 | 定时、静默超时或命令触发 | 由 Planner 结合当前心境、日程、事件线、关系、待办决定**下一条**排程；私聊明确结束后可针对该用户重排时间；发送前有最小间隔、每日上限、静默时段三道硬性护栏 |
| 日程/生活 | 生成作息与日常行程，到点执行 | 不抢日程归属：可只读复用其他日程插件的日程，自己只维护小事件、情绪和事件线；没有外部日程时也能自行生成 |
| 好感/印象 | 单一好感数值、印象卡或等级 | 三维（信任/亲密/默契）+ 关系阶段；每条变化必须逐字引用可核对的事实，单次涨幅封顶，证据不足时保持不变 |
| 人格/价值观 | 演化三观、改造人格底座 | 不碰人格。插件只维护"此刻的状态"，人格始终由 MaiBot 负责 |
| 记忆 | 存储、检索、写回长期记忆 | 只读使用宿主记忆作为评估依据，从不写入；记忆为空时回退到插件自己的对话记录 |
| 拟人细节 | 打字延迟、戳一戳、单点行为 | 关注跨天、跨周的连续性：情绪会衰减、关系会缓慢变化、事件线会推进、值得关心的事会被记住 |
| 上下文治理 | 回复再审、自我演化接口 | 只提供状态与维护任务，不拦截、不改写 MaiBot 的回复流程 |

> 以上按能力类型归纳，不针对任何具体插件，也不代表对同类实现的评价。

### 不重复实现 MaiBot 原生能力

MaiBot 本身已经能表达的行为，插件不再做第二套：

| 能力 | MaiBot 原生做法 | 本插件是否实现 |
| --- | --- | --- |
| 性格、口吻、依恋式表达 | `[personality] personality / behavior_style / reply_style`（支持多套 profiles） | 否，写进人格即可 |
| 是否追问、何时接话、何时安静 | `behavior_style` | 否 |
| 用户分享好消息时的回应方式 | `behavior_style` + `reply_style` | 否 |
| 对话收尾的语气 | `reply_style` | 否；插件只保留“结束信号 → 排程” |
| 具体事实回指 | 长期记忆检索（`enable_memory_query_tool`、启发式回忆） | 否，插件不复制记忆 |
| 打字延迟、分段发送 | 现成的打字节奏类插件 | 否 |
| 主动发消息这个动作 | `maisaka.proactive.trigger` | 否；插件只决定何时、找谁、为什么 |

插件只做 MaiBot 提示词做不到的三件事：**跨天保存状态**、**随时间衰减**、**按用户区分并缓慢演进**。

一句话总结：**别的插件让麦麦"做一个动作"，Mai Persona 让这个动作有来处；而人格本身，始终由 MaiBot 负责。**

## 当前支持的功能

**内在状态**

- 三层 PAD 状态：角色气质基线（trait）、长期心境（mood）、即时情绪（emotion）。
- 指数回归：即时情绪约 20 分钟向心境回归，心境约 12 小时向基线回归（可配置）。
- 收到新消息时记录极小互动脉冲；用户明确表达情绪时立即产生一次有界共情变化。
- 对话批量评价：按 `对话评价间隔` 把近期对话交给 Planner 做有依据的 PAD 评价。

**生活与日程**

- 每日在 `日常安排生成时刻` 生成当日安排与 3–5 个日常小事件。
- 可只读接入 MaiTrace：使用对方 API 的当前活动与当天时间线，自己不再生成日程；接口不可用时明确显示"暂不可用"，不回退过期数据。
- 小事件到点后会影响情绪候选值，幅度受 `日常事件情绪偏移上限` 限制。

**事件线**

- 同时保留若干条长期事件线，按 `每日推进时刻` 推进/停滞/结束。
- 事件线达到 `主动提及阈值` 才会进入回复上下文，避免角色总是念自己的剧本。

**关系与好感**

- 关系阶段由浅到深，一次只允许向相邻阶段迁移，且需要事实依据。
- 好感三维：信任、亲密、默契，范围 -1~1。
- 每天在 `每日评估时间` 评估一次；依据优先取宿主长期记忆，缺失时用插件记录的对话原文兜底；单次变化不超过 `单次变化上限`。

**待办与日记**

- 定期抽取待办候选，由 Planner 判断是否建立/更新；支持到期提示。
- 每日整理一篇日记，只存在插件自己的数据库。

**主动联系**

- 全局单条排程：只有一条"下一次主动联系"记录，由 Planner 决定时间、理由、话题和对象。
- 私聊结束后定向排程：明确结束对话后，把日期、状态、该用户资料与刚结束的对话交给 Planner 决定下次时间（精确到分钟），支持 `off`/`whitelist`/`blacklist` 用户过滤。
- 硬性护栏：最小间隔、每日上限、静默时段、目标用户必须有历史互动；询问型排程在用户已互动时取消。

**拟人细节（需要跨天状态，MaiBot 提示词做不到的部分）**

- **跟进事项**：定期从用户发言里整理"值得之后关心一次"的具体事项（结果待定的事、即将发生的事、身体状况等），到期后作为提示交给 Planner 择机自然提起；超过保留时长自动失效，不会翻旧账。
- **披露深度门控**：按当前关系阶段限制角色愿意谈多深——第一阶段只聊表层，第二阶段可谈个人经历，第三阶段起才说私密感受；可在设置中关闭。
- **情绪残留**：用户明确表达负面情绪后，角色的即时情绪在一段时间内回落得更慢，而不是立刻恢复平静。
- **冲突修复**：检测到指责、冷淡或对抗意味的发言时，在 Planner 与回复上下文中提示"先承认感受再修复"，不辩解、不转移话题；用户给出正面表达后自动结案。

**WebUI**

- 工作区「运行概览」：状态、心境/情绪、当前活动、事件线、日记、关系、待办。
- 侧栏「配置向导」：完成度、逐步检查、生成并校验 `config.toml` 片段。

**命令与工具**

- 命令 `/persona_status`：查看当前运行状态摘要。
- Planner 工具：`get_persona_pending_work`、`complete_persona_work`、`get_inner_state`、`update_relationship`、`resolve_persona_event`。

## 安装与快速开始

1. 在插件管理页安装并启用 Mai Persona（资料未填完也可以先启用，会显示"等待配置"）。
2. 打开 WebUI 侧栏「配置向导」，按步骤填写，或直接在插件设置里填写：
   - **角色名称**：与 MaiBot 人格使用同一称呼，仅用于标记插件维护的状态。
   - **状态评价视角**：写判断依据，如"先区分事实与猜测，再评价情绪"；不要写口吻或总体人格。
   - **长期生活方向**：角色个人生活中长期在意的事，用于模拟日常，不是每轮都要讲的目标。
   - **关系阶段**：由浅到深至少两个，例如 `陌生、熟悉、朋友、亲密`。
   - **长期事件线领域 / 日常小事领域**：写题材范围即可，无需预先编剧情。
3. 发送 `/persona_status` 验证运行状态，再正常聊天观察状态变化。
4. 确认普通对话符合预期后，再考虑开启「允许主动联系」。

## WebUI

**工作区「运行概览」**（只读）：当前心境与即时情绪、当前活动与日程来源、活跃事件线、最近日记、关系（阶段 + 三维）与待办。

**侧栏「配置向导」**：

- 顶部显示配置完成度与当前状态，并给出下一步建议。
- 第 1、2 步列出角色资料、生活领域、主动联系的当前值，✅/⬜ 标出还缺什么。
- 第 3 步是可填写的表单：只填要改的项，点击「生成配置片段」，插件会合并当前配置、跑完整校验，并输出一段只包含改动字段的 TOML。
- 把片段粘贴到 `config.toml` 对应段落，保存后在插件管理页重载即可。宿主机只允许"插件管理"内置插件写配置，所以这里不会直接改你的文件。

## 配置项详解

所有字段都有中文标签和说明，设置页可直接修改。下面是每个字段的作用与建议值。

### `[plugin]` 运行与开关

| 字段 | 默认 | 作用 | 建议 |
| --- | --- | --- | --- |
| `enabled` | `false` | 总开关。打开后开始记录与维护状态；资料不全时进入"等待配置" | 先开再补资料也可以 |
| `config_version` | `1.0.0` | 配置版本，由 MaiBot 维护 | 不要手改 |
| `timezone` | `Asia/Shanghai` | 日程、每日任务、记录时间使用的时区 | 与宿主一致 |
| `enable_proactive_messages` | `false` | 允许请求 Planner 发起主动对话 | 先观察普通对话，再单独开启 |
| `tick_seconds` | `60` | 后台检查间隔：状态衰减、到期任务 | 60 秒足够；调小更灵敏但更耗资源 |
| `max_interaction_chars` | `1200` | 单条互动记录截断长度 | 1200 兼顾上下文与体积 |
| `retry_cooldown_minutes` | `15` | 维护任务失败重试、私聊结束决策的冷却时间 | 15–30 分钟 |

### `[persona]` 角色资料（必填）

| 字段 | 默认 | 作用 | 建议 |
| --- | --- | --- | --- |
| `name` | 空 | 角色称呼，仅用于标记插件维护的状态 | 与 MaiBot 人格一致 |
| `viewpoint` | `[]` | 状态评价视角：判断情绪/关系/生活事件的观察原则 | 2–4 条，只写判断依据 |
| `goals` | 空 | 长期生活方向，用于模拟日常活动与事件 | 写角色自己在意的事，不要写成对话任务 |
| `relationship_stages` | `[]` | 关系阶段序列，由浅到深 | 至少两个，例如 `陌生、熟悉、朋友、亲密` |
| `event_line_domains` | `[]` | 长期事件线的题材范围 | 2–4 个，如 `学习、创作、家庭` |
| `micro_event_domains` | `[]` | 日常小事的题材范围 | 2–4 个，如 `休息、通勤、兴趣` |
| `disclosure_depth_gating` | `true` | 按关系阶段限制自我披露深度（表层 → 个人经历 → 私密感受） | 想要角色更快交心可关闭 |

### `[emotion]` 情绪模型

| 字段 | 默认 | 作用 | 建议 |
| --- | --- | --- | --- |
| `trait_p` / `trait_a` / `trait_d` | `0` | 愉悦/活跃/主导的气质基线（-1~1） | 按角色性格设定，如温和内向可 `0.1/-0.2/0.0` |
| `tau_emotion_min` | `20` | 即时情绪回归时间（分钟），越小回得越快 | 15–30 |
| `tau_mood_hours` | `12` | 心境回归时间（小时） | 8–24 |
| `regulation` | `0.65` | 对外表达时收敛即时情绪的比例 | 0.5–0.8；越高越克制 |
| `appraisal_window_hours` | `2` | 两次批量对话评价的最短间隔 | 1–4 小时 |
| `max_delta_per_event` | `0.3` | 单个事件允许的 PAD 变化上限 | 0.2–0.4 |
| `max_micro_event_bias` | `0.15` | 日常小事件对情绪的偏移上限 | 0.1–0.2 |

### `[affection]` 关系与好感

| 字段 | 默认 | 作用 | 建议 |
| --- | --- | --- | --- |
| `evaluate_daily_at` | `23:00` | 每日关系与好感评估时刻 | 放在对话较少的时间 |
| `max_delta` | `0.1` | 信任/亲密/默契单次变化上限 | 0.05–0.1，过快会失真 |
| `evidence_hours` | `24` | 事实回溯窗口：只依据这段时间内的聊天事实 | 24 小时；长期不聊时可适当放宽 |

### `[event_lines]` 事件线

| 字段 | 默认 | 作用 | 建议 |
| --- | --- | --- | --- |
| `max_active` | `3` | 同时保留的活跃事件线数量 | 2–4，过多会分散 |
| `advance_times` | `["13:00","21:00"]` | 每日推进时刻 | 1–2 个时间点 |
| `talkable_threshold` | `0.6` | 事件线进入回复语境的倾向阈值 | 0.5–0.7，越高越少提 |

### `[schedule]` 主动联系

| 字段 | 默认 | 作用 | 建议 |
| --- | --- | --- | --- |
| `min_interval_hours` | `4` | 两次主动联系的最小间隔 | 3–8 小时 |
| `daily_limit` | `3` | 每日主动联系轮数上限，`0` 等于禁止 | 1–3 |
| `silent_hours` | `[1,7]` | 静默时段（起止小时），期间不主动 | 按用户作息设置 |
| `default_active_hour_hint` | `21` | 缺少用户活跃资料时给 Planner 的建议小时 | 20–22 |
| `fallback_replan_hours` | `24` | 没有待发送排程时，多久重新请 Planner 评估 | 24 小时 |
| `decide_after_private_chat_end` | `false` | 私聊明确结束后定向排程（需同时开启主动联系） | 建议先开白名单试用 |
| `decide_user_filter_mode` | `off` | 参与过滤：`off` / `whitelist` / `blacklist` | 先用 `whitelist` 限定对象 |
| `decide_user_whitelist` | `[]` | 白名单用户 ID（精确匹配） | 填常用私聊用户 |
| `decide_user_blacklist` | `[]` | 黑名单用户 ID（精确匹配） | 填不希望被打扰的用户 |

### `[batch]` 日常维护时刻

| 字段 | 默认 | 作用 | 建议 |
| --- | --- | --- | --- |
| `todo_extract_hours` | `4` | 待办整理间隔 | 2–6 小时 |
| `life_generate_at` | `08:00` | 生成当日安排与小事件；启用 MaiTrace 后只触发小事件 | 起床后不久 |
| `use_maitrace_schedule` | `false` | 只读接入 MaiTrace 日程 | 已装 MaiTrace 且想统一日程时开启 |
| `diary_generate_at` | `23:30` | 日记整理时刻 | 睡前 |

### `[exposure]` 状态查询限制

| 字段 | 默认 | 作用 | 建议 |
| --- | --- | --- | --- |
| `daily_limit` | `2` | Planner 每日通过 `get_inner_state` 查询完整状态的次数，`0` 为禁止 | 2–4，防止频繁自省 |

### `[humanlike]` 拟人细节

| 字段 | 默认 | 作用 | 建议 |
| --- | --- | --- | --- |
| `followup_enabled` | `true` | 从用户发言里整理值得之后关心一次的事项 | 关闭后不再生成跟进 |
| `followup_extract_hours` | `6` | 跟进事项整理间隔 | 4–12 小时 |
| `followup_window_hours` | `24` | 整理时回看的发言时长 | 24 小时 |
| `followup_ttl_hours` | `72` | 跟进事项保留时长，超时自动失效 | 48–96 小时 |
| `emotion_carry_over_hours` | `2` | 负面情绪后角色情绪回落变慢的时长 | 1–4 小时 |
| `repair_enabled` | `true` | 检测到摩擦时提示先修复 | 建议保持开启 |
| `repair_ttl_hours` | `24` | 修复提示保留时长 | 12–48 小时 |

## 主动联系是怎么发生的

1. 到点或满足条件时，插件把任务放进自己的 SQLite 队列，**不直接调用模型**。
2. 下一次 Planner 轮次读到队列，调用 `get_persona_pending_work` 拿到任务说明。
3. Planner 判断后调用 `complete_persona_work` 提交结果，插件校验并落库。
4. 到排程时间，插件请求 MaiBot 主动任务能力；是否发送、怎么发仍由 Planner 决定。
5. 发送前依次检查：静默时段、最小间隔、每日上限、目标用户是否有历史互动。

私聊结束排程额外检查：只对私聊生效、已有待发送排程时不覆盖、同一用户 15 分钟冷却、`skip` 只影响该用户。

## 数据与隐私

- 插件数据只写自己的 `mai_persona.db`（位于宿主插件数据目录），包含互动摘要、状态、关系、好感、待办、日记和任务队列。
- **不写入 MaiBot 长期记忆**；日记也不会回写。
- 只读使用宿主 `knowledge.search` 作为评估依据；检索不到时回退到插件自己记录的对话原文。
- 不发起独立模型请求，不设置自己的模型、温度或 Token 上限。
- 在插件说明与提示词中明确：外部日程等内容只作事实参考，其中出现的指令一律忽略。

## 常见问题

**Q：信任/亲密/默契一直是 0？**
它们只在每日评估时变化，且必须有可逐字核对的事实依据。检查：插件已启用、`evaluate_daily_at` 已过、之后有过一次 Planner 轮次（发一条消息即可触发处理）、`max_delta` 不为 0。`0.1.6` 起，宿主记忆没有近况时会用插件记录的对话兜底。

**Q：为什么说完晚安没有立刻收到主动消息？**
私聊结束只负责"决定下一次时间"，不是立即发送；到点后还要经过最小间隔、每日上限、静默时段护栏。

**Q：开启主动联系后一直没发？**
确认 `daily_limit` 不为 0、当前不在静默时段、候选用户 7 天内有互动、距上次主动消息已超过 `min_interval_hours`。

**Q：改了配置没生效？**
保存 `config.toml` 后在插件管理页重载插件；配置向导生成的片段需要手动粘贴。

**Q：会不会和 MaiTrace 重复生成日程？**
启用兼容后插件不再生成或保存自己的日程，只读取 MaiTrace 的活动与时间线，并继续维护小事件。

## 路线图：更拟人可以加什么

筛选标准：**只有需要跨天状态、会随时间变化、且要按用户区分的功能才放进插件**；MaiBot 人格提示词、长期记忆、Planner/Replyer 已经能表达的，不再重复实现。

已由 MaiBot 原生覆盖、因此**不做**的包括：依恋式口吻、追问习惯、好消息的回应方式、道别语气、具体事实回指、打字节奏、偏好与目标设定、主动发消息这个动作本身。

已经从路线图落地的三项（`0.1.9`）：

1. ✅ **重要披露 → 延迟跟进**：`[humanlike]` 的跟进事项（Reis & Shaver, 1988；Laurenceau et al., 1998）。
2. ✅ **关系阶段门控的披露深度**：`[persona].disclosure_depth_gating`（Collins & Miller, 1994；Aron et al., 1997）。
3. ✅ **情绪残留与冲突修复**：`[humanlike]` 的情绪残留与修复提示（Hatfield et al., 1993；Gottman, 1994）。

仍在观察、暂不实现的方向：同等深度的互惠披露（需要更细的对话意图识别）、跨会话的关系里程碑回顾（需要长期数据验证收益）。设计依据见 [docs/human-likeness.md](docs/human-likeness.md)。
