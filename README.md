# Mai Persona

Mai Persona 是 MaiBot 第三方插件，为角色维护情绪与心境、日常安排、事件线、用户关系、待办和日记，让长期互动更有连续性和拟人感。

**人格边界：MaiBot 自有人格设置是角色身份、总体行为准则和回复风格的唯一来源。** Mai Persona 只补充内在状态与个人生活模拟，不覆盖 MaiBot 的人格，也不改变本轮用户任务的优先级。

## 普通用户配置

1. 先在 MaiBot 原有设置中完成角色身份、人格、行为准则和回复风格。插件不会替代这些设置。
2. 将整个 `mai-persona` 目录放入 MaiBot 的 `plugins/` 目录，在插件管理页加载 Mai Persona 并打开设置。
3. 在“状态与生活模拟”中填写角色名称。建议与 MaiBot 原有人格使用相同称呼；这里仅用于标记插件维护的角色状态。
4. 填写“状态评价视角”，写状态判断依据即可，例如“先区分事实与猜测，再评价情绪”“单次未回复不直接视为关系变差”。不要填写说话口吻、总体人格、行为准则或对用户的要求。
5. 填写“长期生活方向”，描述角色在个人生活中持续在意的事情，例如学习、创作或保持生活节奏。它用于模拟日常活动与事件，不是每轮对话必须完成或向用户宣讲的目标。
6. 按由浅到深填写至少两个“关系阶段”，再填写“长期事件线领域”和“日常小事领域”。写题材范围即可，无需预先编写剧情。
7. 启用插件。配置不完整时仍可启用，插件会显示“等待配置”；补齐必填角色资料后自动启动。
8. 在聊天流发送 `/persona_status` 验证运行状态，再正常聊天观察状态是否逐步变化。主动联系默认关闭，建议确认普通对话符合预期后再单独开启。

如插件补充资料与 MaiBot 自有人格、行为准则、回复风格或当前用户明确任务冲突，以 MaiBot 原生配置和本轮任务为准。插件中的状态评价原则和生活方向不应被用来重写角色的整体性格或表达方式。

## 工作流程

1. 插件定期生成待维护事项并放入自己的 SQLite 队列，不启动独立模型请求，也不会在没有对话时唤醒 Planner。
2. 收到一条新的真实用户消息时，插件先记录一枚极小、可恢复的即时互动脉冲；用户明确表达开心、焦虑、难过等情绪时，会立即记录一枚更明确的共情情绪变化。它们不直接改变关系阶段或长期心境。
3. Planner 请求前，插件把内在状态和待办提示作为补充上下文加入 MaiBot 工作流；Planner 可通过插件工具完成有事实依据的深度评价、生活事件、关系和待办维护。
4. Replyer 请求前，插件再次注入当前心境、即时情绪、对外表达 PAD、活动、关系和待办摘要，让本轮回复能感知刚刚变化的状态。
5. Planner 按任务要求完成状态、日常安排、事件线、待办或日记判断，并提交结果。插件校验结果后更新自己的状态数据。
6. 正常对话仍使用 MaiBot 原有 Planner 和 Replyer；插件只补充状态信息，不单独设置回复模型、温度、Token 数或全局回复风格。
7. 只有显式开启“允许主动联系”后，插件才会请求 MaiBot 主动任务能力；是否发送及最终回复仍由 MaiBot Planner 工作流处理。

## 记忆与数据

- 不需要设置记忆插件 ID、记忆检索 API 或画像 API。
- Mai Persona 不写入 MaiBot 长期记忆。若 MaiBot 提供只读记忆检索能力，插件可用已有聊天记忆作为状态评价的事实依据。
- 插件自己的互动摘要、状态、关系、待办和日记保存在数据目录的 `mai_persona.db` 中；日记不会写回 MaiBot 长期记忆。

## WebUI

MaiBot WebUI 工作区的“Mai Persona”页面提供只读概览，可查看当前状态、事件线、日记、关系和待办。

## 完整配置

用户可见字段、说明和示例均为简体中文。配置模型位于 `mai_persona/config.py`，完整 TOML 示例位于 `config.example.toml`：

- `[plugin]`：启用状态、时区、后台检查频率、互动记录上限、失败重试间隔和主动联系开关。
- `[persona]`：角色称呼、状态评价视角、长期生活方向、关系阶段和生活事件领域。
- `[emotion]`：PAD 基线、状态回归速度、评价频率和影响上限。
- `[affection]`：每日关系评估时刻、变化上限和事实回溯时长。
- `[event_lines]`：活跃事件线数量、每日推进时刻和提及阈值。
- `[schedule]`：主动联系频率、每日上限、静默时段和重新评估间隔。
- `[batch]`：待办整理、日常安排和日记整理时刻，以及 MaiTrace 日程兼容开关。
- `[exposure]`：Planner 每日查询完整内在状态的次数上限。

设置页可直接配置。需要本地 TOML 时，复制 `config.example.toml` 为 `config.toml`；`.gitignore` 已排除本地配置与运行数据。请勿提交包含个人角色资料的 `config.toml`。

### MaiTrace 日程兼容

在设置页“日常维护任务”中开启“使用 MaiTrace 日程”即可。该选项默认关闭；开启后 Mai Persona 会每 5 分钟只读获取一次当前活动快照，并将当前活动和接下来的活动注入 Planner、Replyer 与 WebUI。Mai Persona 不会再生成或保存自己的日程，但仍会维护日常小事件、情绪和事件线。

MaiTrace 以 `Rabbit-Jia-Er.MaiTrace` 插件 ID 暴露 `get_current_activity` 和 `get_schedule(day)` 只读 API。请同时安装并启用 MaiTrace，并确认其日程功能已启用。兼容层通过 MaiBot SDK 的插件 API 代理读取当前活动和当天时间线，不直接依赖对方代码，也不会修改对方的日程数据。若接口未安装、未启用或调用失败，Mai Persona 会显示“暂不可用”，不会回退展示可能过期的本地日程；可在日志中查看具体错误。

WebUI 的日程区显示当前活动、MaiTrace 当天已记录的时间线和后续活动概览。MaiTrace 只返回其 API 可见的日程，不包含插件未公开的数据。

兼容开启期间，`[batch].life_generate_at` 仍用于触发 Mai Persona 的日常小事件生成。关闭兼容后恢复由 Mai Persona 自行生成日程。

## 测试

在插件目录运行：

```powershell
python -m unittest discover -s tests -v
python -m compileall -q plugin.py mai_persona tests
```

建议验证：角色资料未填完时插件仍可加载；补齐资料后自动启动；Planner 能提交并保存有效维护结果；无效结果保留重试；关闭主动联系时不会触发主动任务。

## 兼容范围

插件使用 `maibot-plugin-sdk` `2.20.x` 配置、Hook、工具和能力接口，面向 MaiBot `1.3.x`。
